# Native 后端评估与方案

本文档评估了为 Valkyrie 编译器添加原生指令集（x86, x64, arm64, riscv）支持的方案。

## 方案概览

支持原生指令集有三种主要路径，每种路径的切入点和工作量各不相同。

### 方案 A：基于 Cranelift (推荐)

Cranelift 是一个高性能、跨平台的代码生成器，完全由 Rust 编写，旨在作为 LLVM 的轻量级替代品。

- **切入点**: **SSA (Static Single Assignment)**
- **优点**:
    - 编译速度极快（适合 JIT 和快速 AOT）。
    - 纯 Rust 实现，集成简单。
    - 已经处理了寄存器分配、指令选择和多种平台支持。
- **工作量**: 实现 `SsaProgram` 到 `Cranelift IR` 的转换。

### 方案 B：基于 LLVM

LLVM 是工业界的标准，提供了最强大的优化能力。

- **切入点**: **SSA (Static Single Assignment)**
- **优点**:
    - 极佳的运行时性能。
    - 支持几乎所有已知的硬件平台。
    - 极其成熟的生态系统。
- **缺点**:
    - 依赖笨重的 LLVM 库（C++）。
    - 编译时间较长。
- **工作量**: 实现 `SsaProgram` 到 `LLVM IR` 的转换。

### 方案 C：自定义后端 (寄存器机模型)

直接在 `LIR` 基础上编写针对特定架构的发射器（Emitter）。

- **切入点**: **LIR (Low-level IR)**
- **优点**:
    - 零外部依赖。
    - 完全控制生成的机器码。
    - 可以针对 Valkyrie 运行时进行深度优化（如代数效应的特殊处理）。
- **缺点**:
    - 巨大的工作量（需要为每个架构编写寄存器分配器和指令选择器）。
- **工作量**: 基于 `LIR` 实现针对 x64/arm64 的汇编发射器。

## 技术选型建议

### 1. 短期目标：Cranelift
作为第一个原生后端，**Cranelift** 是最佳选择。它与 Valkyrie 的 SSA 结构高度匹配，且能够同时满足 AOT 和未来可能的 JIT 需求。

### 2. 长期目标：LLVM
对于追求极致性能的发布版本，可以引入 LLVM 后端作为可选组件。

### 3. 特殊需求：自定义 LIR 转换
如果需要极致精简的嵌入式运行时，或者现有的后端难以支持 Valkyrie 的代数效应（Algebraic Effects）和延续（Continuations），则考虑从 LIR 直接生成机器码。

## 实施路径

1. **第一阶段 (调研)**:
   - 评估 `valkyrie-types` 中的 `SsaProgram` 是否包含 Cranelift 所需的所有语义信息。
   - 实验性实现一个简单的 `Ssa -> Cranelift` 转换器，支持加法和返回。

2. **第二阶段 (基础实现)**:
   - 实现完整的类型映射。
   - 实现函数调用规约（Calling Convention）的处理。
   - 实现基本块的线性化。

3. **第三阶段 (高级特性)**:
   - 处理代数效应（可能需要特殊的栈操作或运行时支持）。
   - 实现调试信息（DWARF）生成。
