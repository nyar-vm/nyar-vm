# 文件级动态技术 (File-level Dynamic Technology)

Nyar VM 的文件级动态技术主要关注模块的动态加载、符号链接以及扩展插件的集成。这套机制使得 Nyar 能够实现高度的模块化和运行时可扩展性。

## 1. 动态模块加载 (Dynamic Module Loading)

Nyar VM 并不要求在启动时加载所有代码。通过 `load_module` 接口，虚拟机可以在运行时按需加载 `.nyar` 字节码文件。

- **模块结构**：每个 `.nyar` 文件对应一个 `NyarcModule` 对象，包含常量池、代码块（Chunks）、类定义、Trait 实现以及导入导出元数据。
- **按需解析**：模块的导入（Imports）描述了其依赖项，加载器会根据这些信息递归地解析并载入依赖模块。

## 2. 运行时符号链接 (Runtime Symbol Linking)

Nyar 采用了延迟绑定的策略。跨模块的函数调用或全局变量访问在编译期仅保留符号名称。

- **全局符号表**：虚拟机维护一个全局 `symbol_table`。当新模块加载时，其 `exports` 列表中的符号会被注册到表中。
- **动态解析**：执行 `CallSymbol` 或 `LoadGlobal` 指令时，VM 会在符号表中实时查找目标地址，从而实现模块间的透明调用。

## 3. 插件系统与 FFI：运行时环境适配

FFI（外部函数接口）是 Nyar 与原生世界交互的桥梁，而插件（Plugin）系统则是解决跨环境适配的核心。

- **运行时环境依赖**：FFI 调用本质上是平台相关的。例如，一个在 Windows x86 环境下编译的原生 C 函数，显然无法在 WebAssembly (WASM) 运行时中直接执行。
- **插件的意义**：这正是 Nyar 插件系统的核心价值所在。
    - **特定声明**：每个插件只声明其支持的特定 `ffi native call`。
    - **环境隔离**：通过 `ModuleLoader` 接口，虚拟机可以根据当前的运行环境（Native, WASM, JS 等）选择性地加载匹配的插件实现。
    - **动态注册**：`FFIRegistry` 允许在运行时动态注册函数。如果某个原生调用在当前环境下不可用，系统可以优雅地回退到纯字节码实现或报错，而不是导致整个 VM 崩溃。
- **ModuleLoader Trait**：开发者可以实现自定义的加载器，根据环境元数据（如 `target_arch`, `os`）来决定如何映射 `FFICall` 指令。

## 4. 链接器配置

在项目配置文件（如 `nyar.json` 或 `project.md`）中，可以对链接行为进行微调：
- `lto`: 是否开启链接时优化。
- `static`: 是否尝试静态链接依赖。
- `strip`: 是否移除符号信息以减小体积。

通过这些技术，Nyar VM 构建了一个灵活且强大的生态系统，支持从简单的脚本执行到复杂的多模块应用开发。
