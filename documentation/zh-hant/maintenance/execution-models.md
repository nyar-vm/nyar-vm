# Valkyrie 執行模型

## 1. 概述

Valkyrie 旨在支持多種執行環境，從高性能的生產環境到高度交互的開發環境。

## 2. 多出口後端架構

Valkyrie 採用**多出口後端架構 (Multi-Export Backend Architecture)**。雖然編譯器前端（AST -> HIR -> CFG -> SSA -> LIR）是線性下降的，但並非所有後端都必須從 LIR 開始轉換。

每一層 IR 都有其獨特的結構優勢，適合對接不同的目標平台：

- **SSA (Static Single Assignment) -> LLVM IR**: 
    - LLVM 本身就是基於 SSA 的，直接從 Valkyrie SSA 轉換可以保留最豐富的數據流信息，方便 LLVM 進行深度優化。
- **CFG (Control Flow Graph) -> WASM**: 
    - WASM 是一種結構化控制流格式（Structured Control Flow）。直接從 CFG 轉換可以更容易地恢復 WebAssembly 所需的 `block`, `loop`, `if` 等結構，避免在 LIR 扁平化後再進行昂貴的控制流恢復。
- **HIR (High-level IR) -> C / Source-to-Source**: 
    - HIR 保留了高級語法信息（如 Traits, 類型定義）。如果需要導出為 C 代碼或進行源碼轉譯，HIR 是最佳入口。
- **LIR (Low-level IR) -> 解釋執行 / AOT**:
    - LIR 是為高性能虛擬機設計的，適合直接解釋執行或通過簡單的 AOT 編譯為 native 機器碼。

## 3. LIR 寄存器模型決策

Valkyrie 的 LIR 選擇了**寄存器模型 (Register Machine)** 而非棧模型，其核心考量如下：

### 3.1 為什麼選擇寄存器模型？

1.  **減少調度開銷 (Dispatch Overhead)**:
    - 棧模型通常需要大量的 `push`/`pop` 操作，對於虛擬機而言，這些操作會顯著增加指令數量。
    - 寄存器模型允許一條指令完成多個操作（如 `add r1, r2, r3`），減少了指令解碼和分發的頻率。
2.  **代數效應與狀態快照 (Snapshots for Algebraic Effects)**:
    - Valkyrie 支持代數效應（Algebraic Effects），需要頻繁地對執行狀態（Frame）進行快照和恢復。
    - 在寄存器模型中，狀態被平鋪在 `Vec<Value>` 中。創建快照只需一次 `clone()`，恢復狀態只需替換指針。
    - 相比之下，棧模型的快照需要處理複雜的棧幀偏移和深拷貝，效率較低。

### 3.2 為什麼不是無限寄存器？

雖然虛擬機可以模擬無限寄存器（SSA 風格），但 Valkyrie LIR 選擇了**動態有限寄存器**：

1.  **內存足跡與快照性能**:
    - 無限寄存器會導致 `Frame` 中的寄存器數組異常龐大，且充滿空洞（稀疏）。
    - 每一條 `Yield` 指令都會產生快照。如果寄存器數量過多，快照的內存開銷和複製成本將不可接受。
2.  **局部性優化**:
    - 有限的寄存器強制編譯器進行簡單的寄存器分配（Register Allocation），使得數據在內存中更加緊湊，提高 CPU 快取命中率。

### 3.3 為什麼不是固定 256 個寄存器？

1.  **避免溢出 (Spilling)**:
    - 固定的 256 個寄存器（如 LuaVM 或早期虛擬機）在處理超大函數或深度嵌套的表達式時，容易出現寄存器不足的情況，被迫將數據溢出到棧內存，導致性能斷崖式下降。
2.  **按需分配**:
    - Valkyrie LIR 的每個函數擁有獨立的 `register_count`。
    - **小函數**: 只占用極少的寄存器，快照極快。
    - **複雜函數**: 自動擴展寄存器數量，保證不發生溢出。
    - 這種靈活性在處理大量微型閉包和協程時具有顯著優勢。

### 2.1 解釋執行 (Interpreted Execution)

在開發和調試階段，Valkyrie 使用內建的虛擬機 (`ValkyrieVM`) 直接解釋執行 LIR。

- **優勢**:
  - **快速啟動**: 無需漫長的機器碼生成過程。
  - **熱重載**: 可以在不重新編譯整個程序的情況下替換函數。
  - **深度調試**: 解釋器可以直接訪問所有運行時狀態。

### 2.2 靜態編譯 (Static Compilation)

在生產部署階段，LIR 可以進一步降級為目標機器碼（如 WASM 或原生指令）。

- **目標平台**:
  - **WebAssembly (WASM)**: 面向現代瀏覽器和伺服器端 WASM 運行時。
  - **原生二進制**: 通過後端生成器（規劃中）生成高性能機器碼。

## 3. 運行時特性

無論是解釋執行還是編譯執行，Valkyrie 都提供統一的運行時支持：

- **代數效應 (Algebraic Effects)**: 通過棧式處理程序實現高效的控制流跳轉。
- **自動內存管理**: 基於垃圾回收（取決於配置）的內存管理。
- **元編程支持**: 運行時反射與動態類型檢查。
