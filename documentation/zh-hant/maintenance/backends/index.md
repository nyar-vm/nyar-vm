# 後端維護指南

本文檔介紹了 Valkyrie 編譯器支持的各種後端的編譯流程和設計考量。

## 概覽

Valkyrie 支持多個後端，每個後端都有其自身的特性和優化策略。通用流水線為：
`Source -> AST -> HIR -> CFG -> SSA -> LIR -> Target`

然而，根據目標架構（基於棧 vs 基於寄存器）的不同，某些階段可能會被跳過或修改。

## 後端實現

- [JVM 後端](jvm.md): 針對 Java 虛擬機，採用基於棧的架構。
- [WASM 後端](wasm.md): 針對 WebAssembly，採用基於棧的架構。
- [CLR 後端](clr.md): 針對 .NET 運行時，採用基於棧的架構。
- [Native 後端](native.md): 針對原生指令集（x86, x64, arm64, riscv）的評估方案。
- [ValkyrieVM](valkyrie-vm.md): 參考解釋器，採用基於寄存器的架構。

## 設計決策

### 針對棧機跳過 LIR 階段

自 2026-01-10 起，我們決定為針對棧機（如 JVM）的後端跳過 LIR 階段。

**理由**：
- **冗餘性**：LIR 是為寄存器機設計的。將 SSA 映射到 LIR 涉及寄存器分配，這對於棧機來說是不必要的。
- **性能**：直接從 CFG（仍保留高層表達式信息）生成基於棧的指令，可以更自然地利用操作數棧，避免過多的局部變量訪問。
