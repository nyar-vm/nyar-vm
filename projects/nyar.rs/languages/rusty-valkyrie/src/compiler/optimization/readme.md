# compiler / optimization

**语言拥有的语义保持变换**：在 **已验证** HIR 或 Semantic MIR 上工作，需要类型、effect、evidence 等事实。

## 组织方式

按 IR 合同分子目录（如 `hir/`、`mir/`），**不** 预先搭建万能 pass 插件框架。每增加一个优化须写明：

- 输入 IR 阶段与验证前提
- 依赖的分析
- 允许改动的节点与须保留的身份
- 使哪些分析失效、之后须再验证什么

根模块承载封闭类静态化、见证消除等优化分析。

## 与其它优化层的区分

| 层级 | 所有者 |
|------|--------|
| 语言语义优化 | 本目录 |
| Nyar 通用优化 | `nyar-emitter` 及对应 Nyar 模块 |
| 目标指令/布局优化 | 目标 backend |

优化是编译流程中的可选变换，输入仍然是已经完成语义检查的 HIR 或 MIR。
